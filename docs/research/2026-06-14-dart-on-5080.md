### pytorch3d build failure (why the shim)

`pip install git+pytorch3d` with `--no-build-isolation FORCE_CUDA=0` compiles the CPU C++ extension, but the
link step fails: the first object (`gather_scatter_cpu`) errors under the env's toolchain and ninja aborts, leaving
the linker unable to find any `.o` files (`ld: cannot find ...gather_scatter_cpu.o`). This is the Blackwell/new-stack
C++ friction the plan flagged. Rather than spiral on it (hypothesis limit), I confirmed by grep that **DART's
text→motion rollout uses only `pytorch3d.transforms`** (`from pytorch3d import transforms`; `pytorch3d.structures`
appears only in scene-collision code, NOT `run_demo`). `pytorch3d.transforms` is pure PyTorch — no compiled `_C`.
So I vendored just `pytorch3d/transforms` + `pytorch3d/common` (sparse-checkout from upstream) into site-packages
with a minimal `__init__.py` that does **not** import `_C`.

- **Adequate for:** the core text→motion rollout (`mld.rollout_demo` / `mld.rollout_mld`) and Stage-3 Phase-2
  axis-angle → quaternion → normalized-VRM conversion.
- **Not adequate for:** scene-interaction demos (`mld.optim_scene_mld`) that touch `pytorch3d.structures`/`_C`.
  If those are needed later, build pytorch3d properly (likely: install a matching CUDA dev toolkit + nvcc, or use
  an older C++ standard / pinned commit).

## THE BLOCKER — SMPL-X / SMPL-H body models (needs the user)

`utils/smpl_utils.py` runs this **at import time** (top of module):

```python
from config_files.data_paths import *            # body_model_dir = data/smplx_lockedhead_20230207/models_lockedhead/
body_model_dict = {
    'male':   smplx.build_layer(body_model_dir, model_type='smplx', gender='male',   ext='npz', num_pca_comps=12),
    'female': smplx.build_layer(body_model_dir, model_type='smplx', gender='female', ext='npz', num_pca_comps=12),
}
```

Without the `.npz` files this raises `ValueError: Unknown model type ...` and **every** demo import dies there.

## Agentic-access notes (reusable)

- Reach the box: `ssh rtx5080 "<cmd>"` (default remote shell is **cmd.exe**).
- Run anything in WSL via the **base64-pipe** pattern to dodge quoting/pipe interception by cmd:
  `ssh rtx5080 "wsl -d Ubuntu-24.04 -u root -e bash -lc \"echo <BASE64> | base64 -d | bash\""`
  — note the **escaped double quotes** around the `bash -lc` arg: cmd.exe does **not** protect `|` inside
  *single* quotes, so single-quoting the pipeline silently breaks it.
- conda: `source /root/miniconda3/etc/profile.d/conda.sh; conda activate dart`.
- Detached jobs on the box **must** use `nohup` — a background `{ … } &` without nohup gets SIGHUP'd the instant
  the `bash -lc` returns (this is why the first checkpoint download died after one line).
- `gdown --folder` on the DART Drive folder **fails** (it chokes traversing the huge `policy_train/` tree of
  hundreds of RL `iter_*.pth`). Download the specific files **by file-ID** instead (`gdown <id> -O <path>`) — works
  cleanly, handles the large-file virus-scan confirm. File-IDs harvested from the folder enumeration are recorded
  in the plan status log.
