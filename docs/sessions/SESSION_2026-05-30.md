## Safety review (companion-safety-reviewer) → BLOCK → fixed
The new agent team's first job: an adversarial privacy/safety audit. It returned **BLOCK** —
the privacy trust spine was built but not wired end-to-end. All findings fixed (commits
`64ce527`, `134cf00`):
- **BLOCK** — `cloud_eligible` was defined but never passed. Added `is_cloud_send(cfg)`
  (provider + endpoint-host heuristic; `openai_compat` resolves local-vs-cloud by host;
  fail-closed) and wired it into the context-assembler RAG search. Private memories no
  longer reach cloud providers.
- **HIGH** — `user_facts` status/privacy columns were dead. Now: injection filters
  status='active' + (cloud) privacy='normal' + drops suppressed-by-hash facts;
  `delete_user_fact` soft-forgets; extractor + both NER auto-insert paths skip suppressed.
- **MED** — hard delete records the suppression hash before purge.
- **LOW** — debug endpoint gates Tier F dials behind nsfw+bond (pure SELECT, no side effect).
- **Accepted/documented** — rituals + private_vocabulary have no per-row privacy; a future
  "keep intimate content local" global toggle is the right home, not a silent per-row gate.

**Re-review** confirmed the 4 above CLOSED and found a **NEW BLOCK I'd missed**:
`intimate_memories` (explicit sensory scene summaries — the most sensitive class) injected
to cloud with no gate. Fixed (`16f7424`) + proactively guarded `intimate_milestones`
(first_kiss/first_intimate) for consistency (`0827ac4`), and forwarded `cloud_eligible`
through the `query_memory` shim. **Final verified guard set (all stored intimate/private
content stays on-device when the send is cloud):** `user_facts` (server.py:3117),
`intimate_milestones` (3391), `intimate_memories` (3426), RAG `search` cloud_eligible
(context_assembler.py:291), shim forwarding (tiered_memory.py:389).
**Line drawn:** *stored* intimate memory content never goes to cloud; *ephemeral* NSFW
scene-state directives are governed by the user's explicit dual opt-in (NSFW mode + cloud
provider). **Found, not fixed (pre-existing, not a leak):** multi-chat `query_memory` is
called with wrong positional args (server.py ~5460) — its RAG is broken (embeds an int);
own fix.
