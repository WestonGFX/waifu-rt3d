## 🏗️ Core Architecture: The "Neuro-Soul" Engine

### 1. HY-Motion-1.0 Integration (Generative Motion)
>
> **Goal**: Replace static `.vrm` animations with generative, context-aware motion.
> **Status**: Planned (Module).

#### The Vision

Current 3D avatars loop through "Idle" and "Talking" states. This feels robotic. **HY-Motion** allows us to generate animation frames *on the fly* based on the semantic content of the conversation.

- If the AI says "I'm so angry!", the model generates a stomping motion.
- If the AI says "Look at this," it points.

#### Implementation Plan (`v6.1`)

1. **The Generation Pipeline**:
    - **Input**: Text Emotion vector + Audio Spectral data.
    - **Model**: `Tencent/HY-Motion` (running in a separate Python process to avoid dependency hell).
    - **Output**: Stream of bone rotations (`.json` or `.bvh`) to the Frontend.
2. **VRAM Management**:
    - The model requires ~4GB VRAM.
    - **Safety Check**: The app will query `nvidia-smi` or `torch.cuda.mem_get_info()` on startup.
    - **Fallback**: If VRAM < 6GB, fallback to "Classic Mode" (pre-canned animations) automatically.
3. **Frontend Interpolation**:
    - The Three.js `AnimationMixer` must smoothly blend between the "Generated" clip and the "Idle" loop to prevent snapping.

#### Optional Paths

- **Cloud Offload**: Allow users to run the motion server on a separate Colab instance and stream data via WebSocket.
- **2D Mode**: Completely disable 3D for a "Vtuber 2D" Live2D-style sprite mode for low-end laptops.

### 2. The "Hippocampus": Vector Database & RAG
>
> **Goal**: Infinite long-term memory and "Lore" lookup.
> **Tech**: `ChromaDB` + `Info-NCE` Embeddings.

#### The Problem

LLMs have a context limit (e.g., 4096 tokens). They forget what you said 20 minutes ago.

#### The Solution: Retrieval Augmented Generation (RAG)

We will treat memory like a search engine.

1. **Episodic Memory**: Every user message is embedded (converted to a number list) and stored.
    - *User*: "My dog's name is Rex." -> `[0.1, 0.5, ...]` -> DB.
2. **Retrieval**: When User says "How is my pet?", we search the DB for "pet/dog".
    - *DB Found*: "My dog's name is Rex."
3. **Injection**: We truthfully paste this into the System Prompt:
    - `CONTEXT: The user has a dog named Rex.`

#### Implementation Plan (`v6.2`)

- **Module**: `waifu-memory` (pip installable).
- **Storage**: `.chromadb/` folder in `backend/storage`.
- **Lore Books**: Support for simple `.json` files defining world info.
  - `{"term": "The Agency", "definition": "A secret organization..."}`
  - When "The Agency" is mentioned, the definition is pulled.

### 3. "The Wizard": Automated Module Installer
>
> **Goal**: One-click setup for complex AI tools. No more terminal commands.

#### concept

A new "Modules" tab in the Settings UI. It looks like an App Store.

#### Planned Modules (The "Big List")

1. **Core Audio**
    - `FFmpeg-System`: Checks system PATH. Offers to install via Brew/Choco.
    - `Audio-Router`: Virtual Cabling setup helper.
2. **Speech Recognition (ASR)**
    - `Faster-Whisper (Tiny)`: Low RAM, fast.
    - `Faster-Whisper (Large-v3)`: High accuracy, slow.
    - `Deepgram-API`: Cloud alternative.
3. **Text Generation (LLM)**
    - `Llama-3-8B-Quant`: Standard model downloader.
    - `Mistral-7B-Uncensored`: For "Soulful" uncensored chats.
    - `Dolphin-Mixtral`: High intelligence agent.
    - `LM-Studio-Bridge`: Connects to external app.
4. **Text-to-Speech (TTS)**
    - `XTTS-v2`: Cloning capability (High Quality).
    - `Silero`: Ultra-fast CPU TTS.
    - `RVC-v2`: Realtime Voice Conversion post-processing.
5. **Vision**
    - `LLaVA-1.6`: Image interrogation (Show the AI a picture).
    - `Stable-Diffusion-WebUI`: Generate images for the user.

#### Implementation Details

- **The Worker**: A background thread (`installer.py`) that handles `pip` processes and progress bars.
- **The UI**: Realtime progress bars. "Cancel" button. "Auto-Update" toggles.

### 4. Fine-Tuning Wizard (Personality Engine)
>
> **Goal**: "Clone yourself" or your favorite streamer.

#### The Workflow

1. **Data Ingestion**:
    - **Source**: Twitch VODs, Discord Dumps, YouTube Chat Replays.
    - **Parser**: A regex tool to strip timestamps and usernames.
2. **Data Cleaning**:
    - **Deduplication**: Remove spam ("OMEGALUL x10").
    - **Anonymization**: Replace real names with placeholders.
3. **Training (LoRA)**:
    - We will use `unsloth` (a customized training library) for 2x faster training.
    - **UI**: A simple slider for "Creativity" (Learning Rate) and "Retention" (Epochs).
4. **Verification**:
    - A split-screen chat. Left: Original Model. Right: Fine-Tuned Model.

#### Optional Paths

- **Cloud Train**: Upload dataset to RunPod ($0.50/hr) -> Download Adapter.
- **Merge**: Combine multiple personalities (e.g., "Sassy" + "Helpful").

### 5. The "Soulful" UI: Aesthetics & Vitality
>
> **Goal**: The interface should feel like a piece of 90s cyberpunk hardware found in a junk heap, yet powered by super-intelligence.

#### 5.1 Visual Language

- **Palette**: `Void Black` (#000000), `Phosphor Green` (#33ff00), `Error Red` (#ff0055).
- **Shader Effects**:
  - **CRT Curvature**: WebGL shader bending the screen edges.
  - **Scanlines**: Moving lattice overlay.
  - **Signal Noise**: Dynamic grain based on "Stress" levels.

#### 5.2 "Alive" Widgets (The HUD)

The layout should resemble an F-15 Fighter Jet HUD mixed with a Winamp skin.

1. **The "Eye"**:
    - A central pixel-art eye that looks at the mouse cursor.
    - Blinks naturally. Dilates when the LLM is "Processing".
2. **Audio FFT**:
    - Realtime frequency bars that bounce to the TTS voice.
3. **Latency Monitor (The Heartbeat)**:
    - A scrolling EKG graph showing the *exact* ms taken by each module.
    - `[ASR: 200ms] -> [LLM: 1400ms] -> [TTS: 500ms]`
4. **Console Panel**:
    - A Matrix-style scrolling logs printed in real-time.
    - Toggleable via the `~` key (Quake style).
